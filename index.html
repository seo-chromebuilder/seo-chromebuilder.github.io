// Browser boundary

Use Manifest V3 with activeTab and scripting for an explicit, user-triggered inspection. A content script reads the page DOM; a service worker routes messages and requests. A side panel can keep the report beside the inspected page.

  • Capture title, canonical, headings, meta robots and selected JSON-LD.
  • Show the extracted payload for review before sending it.
  • Exclude form values, cookies and unrelated browsing history.
  • Handle restricted pages and navigation without stale reports.
Reference: activeTab →

// Server boundary

Use a backend endpoint such as POST /v1/audits with account authentication, schema validation and per-account quotas. The OpenAI API key belongs in server-side secret storage, never in an extension bundle or browser storage.

  • Enforce input size limits and strip unnecessary page content.
  • Queue inference jobs with bounded retries and backoff.
  • Keep tenant data isolated; redact request logs.
  • Return a job identifier and a validated result envelope.
Reference: OpenAI production guidance →

$ describe audit_engine

Evidence first.
Recommendations second.

Use rules for observable facts. Use AI for explanation and prioritization. Neither a model output nor an audit score is a guarantee of rankings.

MODULE_01

Page signals

Inspect heading hierarchy, title specificity, crawl directives and canonical declarations. Distinguish “not present in this capture” from “missing across the site.”

MODULE_02

Local relevance

Compare declared services and service areas with visible page copy. Surface ambiguous locations, thin service descriptions and unclear customer next steps.

MODULE_03

Business entities

Parse LocalBusiness JSON-LD and compare it with visible business details. Validate syntax separately from Google feature eligibility or ranking impact.

Build an inference contract.

The planned backend sends normalized evidence to the OpenAI Responses API. Structured Outputs constrains the result to a JSON Schema; application checks still need to verify references, handle refusals and reject incomplete responses.

Each recommendation should carry a rule ID, evidence references, a proposed change and a validation step. If the page does not provide enough evidence, return an explicit unknown rather than inventing a business fact.

Read the Structured Outputs documentation →
  • Treat webpage text as untrusted input, never as system instructions.
  • Do not give page content permission to call tools or modify a site.
  • Render model text safely; do not inject generated HTML.
  • Require a human to approve proposed edits.

$ cat development-plan.log

Built in stages.
Tested against reality.

The development plan focuses on a small, useful inspection loop before adding account integrations or broader reporting.

01
DESIGN TARGET

Capture & normalize

Define typed messages, document fingerprints and payload budgets. Test on static pages, client-rendered sites and multiple LocalBusiness entities.

02
IMPLEMENTATION TARGET

Rules & backend inference

Separate rule results from model suggestions. Version prompts and schemas; use timeouts, cancellation and a server-side job record that survives worker suspension.

03
VALIDATION TARGET

Evaluation & failure testing

Build reviewed fixtures for false positives, unsupported claims, malicious page instructions, 429 responses and truncated output. Compare recommendation quality before changing models.

04
BETA TARGET

Client feedback & release review

Test report usefulness with local businesses. Review permissions, privacy disclosures, deletion controls and Chrome Web Store requirements before distribution.

[ Performance budget ]

Hash normalized inputs to avoid duplicate work. Bound output tokens, cap job concurrency and measure latency per stage. Cache only within the correct tenant and permission boundary.

[ Integration boundary ]

On-page inspection does not reveal Business Profile performance or Search Console data. Future integrations require separate account authorization, suitable scopes and any applicable API access approvals.
